## 📐 Методика оценки: Индекс Жаккара

### 🔢 Формула расчёта

Для оценки качества ответов ИИ мы используем **индекс Жаккара (Jaccard Similarity Coefficient)** — математическую метрику для сравнения множеств.

```
                    |A ∩ C|
    J(A, C) = ─────────────────
                |A ∪ C|
```

**Где:**
- **A** (AI) — множество индексов, выбранных ИИ
- **C** (Correct) — множество правильных индексов
- **|A ∩ C|** — количество совпадений (пересечение множеств)
- **|A ∪ C|** — количество уникальных элементов в объединении

### 📊 Диапазон значений

| Значение J | Интерпретация |
|------------|---------------|
| **1.0** | Идеальное совпадение: ИИ выбрал ровно все правильные ответы и ничего лишнего |
| **0.67 — 0.99** | Высокое совпадение: небольшие ошибки |
| **0.33 — 0.66** | Среднее совпадение: есть существенные ошибки |
| **0.01 — 0.32** | Низкое совпадение: много ошибок |
| **0.0** | Полное несовпадение: нет ни одного правильного ответа или выбраны только неверные |

### 🧮 Примеры расчёта

#### Пример 1: Идеальный ответ
```
Вопрос: "Какие препараты применяются при гипертонии?"
Правильные ответы: [1, 2, 3]
Ответ ИИ: [1, 2, 3]

A = {1, 2, 3}
C = {1, 2, 3}
A ∩ C = {1, 2, 3} → |∩| = 3
A ∪ C = {1, 2, 3} → |∪| = 3

J = 3 / 3 = 1.0 ✅
```

#### Пример 2: Частичное совпадение (пропущен ответ)
```
Правильно: [1, 2, 3]
ИИ ответил: [1, 2]

A = {1, 2}
C = {1, 2, 3}
A ∩ C = {1, 2} → |∩| = 2
A ∪ C = {1, 2, 3} → |∪| = 3

J = 2 / 3 = 0.667 🔶
```

#### Пример 3: Лишние ответы
```
Правильно: [1, 2]
ИИ ответил: [1, 2, 4]

A = {1, 2, 4}
C = {1, 2}
A ∩ C = {1, 2} → |∩| = 2
A ∪ C = {1, 2, 4} → |∪| = 3

J = 2 / 3 = 0.667 🔶
```

#### Пример 4: Полное несовпадение
```
Правильно: [1, 2, 3]
ИИ ответил: [4, 5]

A = {4, 5}
C = {1, 2, 3}
A ∩ C = {} → |∩| = 0
A ∪ C = {1, 2, 3, 4, 5} → |∪| = 5

J = 0 / 5 = 0.0 ❌
```

### ✅ Почему индекс Жаккара?

1. **Справедливость** — одинаково штрафует и за пропущенные, и за лишние ответы
2. **Математическая строгость** — стандартная метрика в науке о данных
3. **Интерпретируемость** — значение от 0 до 1 интуитивно понятно
4. **Универсальность** — работает одинаково хорошо для вопросов с одним и несколькими ответами

> 💡 **Важно:** В медицине выбор лишнего препарата = потенциальный вред пациенту.  
> Индекс Жаккара штрафует за лишние ответы, что делает его идеальным для медицинской оценки.

## 🚀 Быстрый старт

### 🔹 Базовый анализ запуска

```bash
# Анализ запуска #1
python analyze.py --run 1

# С деталями по каждому вопросу
python analyze.py --run 1 --detailed

# Экспорт результатов в JSON
python analyze.py --run 1 --json results.json
```

### 🔹 Сравнение моделей

```bash
# Сравнить запуски #1, #2 и #3
python analyze.py compare 1 2 3
```

### 🔹 Поиск сложных вопросов

```bash
# Найти вопросы с J < 0.5 (по умолчанию)
python analyze.py hard

# Свой порог (J < 0.3)
python analyze.py hard --threshold 0.3

# Для конкретных запусков
python analyze.py hard --runs 1 2 -t 0.5
```

## 📚 Полный справочник команд

### 🔍 `--run` / `-r` — Анализ одного запуска

**Синтаксис:**
```bash
python analyze.py --run <ID> [опции]
```

**Опции:**
| Флаг | Описание |
|------|----------|
| `-d`, `--detailed` | Показать детали по каждому вопросу (первые 20) |
| `--json <файл>` | Экспортировать результаты в JSON |

**Примеры:**
```bash
# Простой анализ
python analyze.py --run 1

# С подробностями
python analyze.py -r 5 -d

# Экспорт для отчёта
python analyze.py --run 3 --json report_run3.json

# Комбинация
python analyze.py -r 10 -d --json results.json
```

---

### 📊 `compare` — Сравнение нескольких запусков

**Синтаксис:**
```bash
python analyze.py compare <ID1> <ID2> ... <IDn>
```

**Примеры:**
```bash
# Сравнить 2 модели
python analyze.py compare 1 2

# Сравнить 5 запусков
python analyze.py compare 1 2 3 4 5

# Сохранить вывод в файл
python analyze.py compare 1 2 3 > comparison.txt
```

**Вывод:**
```

======================================================================
Запуск   Модель                  Вопросов    Средний J    Медиана

#2       gemini-2.5-flash-lite        100        0.745      1.000
#3       gpt-5-nano                   100        0.712      0.833
======================================================================
🏆 Лучший: #2 — J = 0.745
```

### 🔎 `hard` — Поиск сложных вопросов

**Синтаксис:**
```bash
python analyze.py hard [опции]
```

**Опции:**
| Флаг | Описание |
|------|----------|
| `--runs`, `-R` | ID запусков для анализа (по умолчанию: последние 5) |
| `--threshold`, `-t` | Порог индекса Жаккара (по умолчанию: 0.5) |

**Примеры:**
```bash
# Все сложные вопросы из последних 5 запусков (J < 0.5)
python analyze.py hard

# Только из запусков #1 и #2
python analyze.py hard -R 1 2

# Более строгий порог (J < 0.3)
python analyze.py hard -t 0.3

# Комбинация
python analyze.py hard --runs 3 4 5 --threshold 0.4
```

**Вывод:**
```
🔍 СЛОЖНЫЕ ВОПРОСЫ (J < 0.5)
======================================================================
 1. [#3] J=0.00 | При каком состоянии противопоказан метформин?...
    Правильно: [2, 3] | ИИ: [1] | ∩=0, ∪=3
 2. [#3] J=0.25 | Какие симптомы характерны для пневмонии?...
    Правильно: [1, 2, 4] | ИИ: [3] | ∩=0, ∪=4
 3. [#1] J=0.33 | Дозировка аспирина при инфаркте?...
    Правильно: [2] | ИИ: [1, 3] | ∩=0, ∪=3
...
======================================================================
```

## 📖 Интерпретация результатов

### 📊 Основные метрики

После запуска анализа вы увидите:

```
📊 АНАЛИЗ ЗАПУСКА #3 | Индекс Жаккара
======================================================================
🤖 Модель: gemma-3-27b-it:free
📅 Дата: 2026-03-31 07:23:05
📐 Метрика: J = |A∩C| / |A∪C|
----------------------------------------------------------------------
📋 Всего вопросов: 482

🎯 СРЕДНИЙ ИНДЕКС ЖАККАРА: 0.697
   Медиана: 1.000
   Диапазон: [0.000 — 1.000]

📈 РАСПРЕДЕЛЕНИЕ РЕЗУЛЬТАТОВ:
   ✅ Идеально (J=1.00):     263 ( 54.6%)
   🔷 Высокий (J≥0.67):       28 (  5.8%)
   🔶 Средний (0.33≤J<0.67):  98 ( 20.3%)
   🔸 Низкий (0<J<0.33):       9 (  1.9%)
   ❌ Нулевой (J=0.00):       84 ( 17.4%)

📋 ПО ТИПУ ВОПРОСОВ:
   🔘 Один ответ (292 шт): средний J = 0.716
   🔀 Несколько (190 шт): средний J = 0.669
======================================================================
```

### 🔍 Что означают метрики?

#### **Средний индекс Жаккара (Mean Jaccard)**
- **0.8 — 1.0** — Отлично 🌟
- **0.6 — 0.8** — Хорошо ✅
- **0.4 — 0.6** — Удовлетворительно ⚠️
- **< 0.4** — Требует улучшения ❌

#### **Медиана**
- **Медиана = 1.0** — более половины вопросов решены идеально
- **Медиана < Среднего** — есть несколько очень плохих ответов, тянущих среднее вниз
- **Медиана > Среднего** — большинство ответов хорошие, но есть выбросы

#### **Распределение**
- **Большой % "Идеально"** — модель хорошо знает материал
- **Большой % "Нулевой"** — есть пробелы в знаниях, стоит изучить эти темы
- **Большой % "Средний"** — модель "где-то рядом", но допускает ошибки

#### **По типу вопросов**
- **Один ответ > Несколько** — модель лучше справляется с простыми вопросами
- **Несколько > Один** — модель лучше понимает сложные взаимосвязи

## 🎯 Типичные сценарии использования

### Сценарий 1: Быстрая проверка модели

```bash
# 1. Запустить тест на 50 вопросах
python run_test.py -m gemma-3-27b-it:free -n 50

# 2. Посмотреть результаты
python analyze.py --run 1

# 3. Если нужно — детали
python analyze.py --run 1 -d
```

---

### Сценарий 2: Сравнение нескольких моделей

```bash
# 1. Протестировать 3 модели на одинаковых 100 вопросах
python run_test.py -m gemma-3-27b-it:free -n 100      # Запуск #1
python run_test.py -m gemini-2.5-flash-lite -n 100    # Запуск #2
python run_test.py -m gpt-5-nano -n 100               # Запуск #3

# 2. Сравнить результаты
python analyze.py compare 1 2 3

# 3. Найти, какие вопросы сложные для всех
python analyze.py hard -R 1 2 3 -t 0.3
```

---

### Сценарий 3: Глубокий анализ ошибок

```bash
# 1. Запустить полный тест (все вопросы)
python run_test.py -m gemini-2.5-pro

# 2. Получить детальный отчёт
python analyze.py --run 5 -d --json detailed_report.json

# 3. Найти самые проблемные темы
python analyze.py hard --runs 5 -t 0.5 > hard_questions.txt

# 4. Сохранить всё в файл
python analyze.py --run 5 -d > full_analysis.txt
```

---

### Сценарий 4: Подготовка отчёта

```bash
# 1. Создать папку для отчётов
mkdir reports/2026-03-31

# 2. Проанализировать все запуски
for i in 1 2 3 4 5; do
    python analyze.py --run $i --json "reports/2026-03-31/run_$i.json"
done

# 3. Сравнить все модели
python analyze.py compare 1 2 3 4 5 > reports/2026-03-31/comparison.txt

# 4. Собрать сложные вопросы
python analyze.py hard -R 1 2 3 4 5 -t 0.4 > reports/2026-03-31/hard_questions.txt
```

## 🛠️ Устранение неполадок

### ❌ Ошибка: "Запуск #X не найден"

**Причина:** Указан несуществующий ID запуска.

**Решение:**
```bash
# Посмотреть последние запуски
python analyze.py

# Или проверить в БД
sqlite3 test_database.sqlite "SELECT id, model_name, timestamp FROM test_runs ORDER BY timestamp DESC LIMIT 5;"
```

---

### ❌ Ошибка: "Нет результатов для запуска"

**Причина:** Тест не был завершён или результаты не сохранены.

**Решение:**
- Проверьте, что `run_test.py` выполнился до конца
- Убедитесь, что в БД есть записи в таблице `results`

---

### ❌ Ошибка: "KeyError: 'timestamp'"

**Причина:** Несовпадение имён колонок в БД.

**Решение:**
```bash
# Проверить структуру таблицы
python -c "
import sqlite3
conn = sqlite3.connect('test_database.sqlite')
cursor = conn.cursor()
cursor.execute('PRAGMA table_info(test_runs)')
for col in cursor.fetchall():
    print(col[1])
"
```

## 🎓 Лучшие практики

### ✅ Рекомендуется

1. **Тестировать на репрезентативной выборке**  
   Минимум 50-100 вопросов для надёжной оценки

2. **Использовать одинаковое количество вопросов при сравнении**  
   `python run_test.py -m model1 -n 100`  
   `python run_test.py -m model2 -n 100`

3. **Анализировать ошибки**  
   Регулярно запускайте `python analyze.py hard` для поиска слабых мест

4. **Экспортировать результаты**  
   Сохраняйте JSON для истории: `--json results_2026-03-31.json`

5. **Смотреть на медиану, а не только на среднее**  
   Медиана лучше показывает типичное качество

---

### ⚠️ Не рекомендуется

1. ❌ Делать выводы по < 10 вопросам
2. ❌ Сравнивать модели, протестированные на разных вопросах
3. ❌ Игнорировать вопросы с J=0 — это важные пробелы
4. ❌ Полагаться только на среднее без анализа распределения
